**Goal:** Resolve feedback items F5.1–F5.8, plus G5 (passphrase set/rotate), G3's "the AI agent should identify the deal stage", and the image19–25 annotations, across the six Lua agents. ## Global Constraints

- Work dir: `$ROOT` (repo root; the CRM lives in `$ROOT/noblestride-crm`, agents are siblings). Branch `feedback/2026-08`. Commit after every task with a conventional-commit message scoped to the agent, e.g. `feat(crm_agent): ...`. Never commit `.env` (only `env.example`).
- **SANDBOX ONLY.** `lua push all --force` targets sandbox. **NEVER** run `lua version promote`, `lua deploy`, `lua push --auto-deploy`, `lua skills deploy`, `lua preprocessors deploy`, or `lua env production …` in this workstream. Decision D5: the agents stay staged for the user's review. Production env values (including `TEAM_PASSPHRASE`) are set only on an explicit go-ahead, which is outside this plan.
- **Sandbox must not point at production.** There is a single write-scoped `AGENT_API_KEY` in the CRM, so pointing a sandbox agent at `https://noble-stride.vercel.app/api/graphql` would give sandbox test chats write access to real data. Instead: run the local CRM (`cd noblestride-crm && npm run dev`), expose it with `cloudflared tunnel --url http://localhost:3000`, and set per agent `CRM_API_URL=https://<tunnel-host>/api/graphql` plus `CRM_AGENT_KEY` = the **local** `AGENT_API_KEY` value read from `noblestride-crm/.env` (never the Vercel/production key).
- Passphrase (G5): `TEAM_PASSPHRASE` and `PASSPHRASE_VERSION` are set **on sandbox only**, via `lua env sandbox -k K -v V` (server-side; no push needed). The chosen sandbox value plus the rotation procedure are recorded in `docs/VERIFICATION-GUIDE-2026-08.md` (Task 10).
- **Block-reply text must be emoji-free and dash-free.** A preprocessor `{action:"block", response}` short-circuits the pipeline, so `format-normalizer` (the postprocessor that strips typographic dashes) never runs on it. Every gate string is therefore written with no emoji (the current `✅` strings all go), no em/en dash (`—`/`–`), and no ASCII hyphen in prose. Hyphens are allowed only inside email addresses, URLs, env-var names and code identifiers.
- **Skills must register tools as `new Tool()` literals** inside the `tools:` array. `lua-cli` resolves a skill's tools statically; a wrapper call such as `withGuard(new Tool())` is an unresolvable CallExpression and the compiler pushes the skill with **zero tools** (this silently stripped every staff tool from prod on 2026-07-21; see the comment in `referal_partner_agent/src/lib/staff-mode.ts`). Never wrap, never build the array dynamically.
- Every wording change ships with its pinning test updated in the same commit: `src/lib/__tests__/persona.test.ts` (crm_agent) or `src/__tests__/persona.test.ts` (all other agents), `src/__tests__/manifest-parity.test.ts` (investor_agent), `src/processors/__tests__/passphrase-gate.test.ts`, `src/processors/__tests__/guardrails.test.ts`.
- `package.json`: bump `lua-cli` to `^3.27.0` in all six agents (currently `^3.18.0`).
- Quality bar per agent: `npx vitest run` green, `npx tsc --noEmit` clean.
- YAGNI: build only what a task lists. No new processors, no new channels, no new CRM mutations from the agent side.

### Verified deviations from the master plan (use these, not the plan's wording)

1. `lua test` supports only `skill | webhook | job` — **there is no `lua test preprocessor`**. `--name` on `lua test skill` is the **tool** name, and it "runs locally, no LLM". Gate/preprocessor logic is therefore verified by vitest only, plus the sandbox chats in Task 9.
2. `webSearch` is **already Active** on both `crm_agent` and `investor-tracker-agent` (`lua features list`). Task 4's `lua features enable --feature-name webSearch` is a verify-or-enable step, not a change.
3. The CRM's GraphQL lives at `noblestride-crm/src/graphql/*` (not `src/server/graphql/*`). Query names `dashboardStats`, `pipelineOverview`, `investorsCount` are real and reachable with `x-agent-key` (no `assertAutomation` on them; `createContext` returns `{type:"AGENT", authenticated:true}` for a matching key). **`PipelineOverview` exposes only `mandatesByStage` and `transactionsByStage`** — the service's `mandatesActive`/`transactionsActive` are *not* in the GraphQL type, so active totals are summed in the tool.
4. Agent-side env var for the CRM key is `CRM_AGENT_KEY`; the CRM-side variable it must match is `AGENT_API_KEY`.
5. `lua skills` has no `deactivate` action (only `view`, `versions`, `deploy`, `delete`). Removing the partner skill server-side is `lua skills delete --skill-name partner-self-service` (preprocessors, by contrast, do have `activate`/`deactivate`).
6. The three passphrase gates are **not** the same file: `crm_agent` has `GateState`/`extractCredentials`/DI'd `runGate`; `investor-tracker-agent` has `gateDecision(verified, lastText, passphrase)` with side effects inline in `execute`; `referal_partner_agent` has the dual-audience `proceed|verify|partner|logout` shape. Task 1 refactors the tracker and Task 7 the referral agent onto the crm_agent `runGate(deps, state, lastText, userId)` shape so the new outcomes are unit-testable without the platform.
7. Every agent uses `env.example` (no leading dot).
8. `investor_agent` has no passphrase gate — its preprocessor is `auto-reply-guard` and identity comes from `verifiedSender()` (email channel only).

```ts
export const HELP_INTENT =
  /(^|\b)(help|how does (this|it) work|how do i (use|start|verify|get started)|what (can|do) you do|what is this|who are you|what are your capabilities|guide me|getting started|what is a pass ?phrase|whats a pass ?phrase|what.s a pass ?phrase|where (do i|does one) (get|find) the pass ?phrase|how (is|was) the pass ?phrase (set|determined|chosen)|why do you need a pass ?phrase)(\b|$)/i;

export function isHelpRequest(text: string | undefined): boolean {
  return typeof text === "string" && text.trim().length > 0 && HELP_INTENT.test(text);

export function currentPassphraseVersion(raw: string | undefined): string {
  const v = (raw ?? "").trim();
  return v === "" ? "1" : v;
}

export function isVerifiedForVersion(
  verified: boolean,
  storedVersion: string | undefined,
  currentVersion: string,
): boolean {
  if (!verified) return false;
  return (storedVersion ?? "1") === currentVersion;
}
```

- [ ] **Step 5: crm_agent gate — new outcomes**

In `crm_agent/src/processors/passphrase-gate.ts`:
- Extend `GateState` with `passVersion?: string`.
- Extend `GateOutcome` with `"help" | "hint_missing_passphrase"`.
- New signature: `gateDecision(state: GateState, lastText: string | undefined, passphrase: string | undefined, passVersion: string)`.
- Decision order in the unverified branch (this is the whole fix — help comes **before** the challenge):
  1. `isHelpRequest(lastText)` → `"help"` (even when `passphrase` is unset, so the visitor still gets the explanation).
  2. `!passphrase` → `"unconfigured"`.
  3. `lastText === undefined` → `"challenge"`.
  4. Passphrase matches (`rest === passphrase.trim()` or whole message equals it) → `"verify_and_identify"` when an email token is present, else `"verify"`.
  5. `extractCredentials(lastText).email !== null` → `"hint_missing_passphrase"`.
  6. otherwise → `"challenge"`.
- Verified branch: compute `verified` as `isVerifiedForVersion(state.verified, state.passVersion, passVersion)`. When the stored version is stale the user falls into the unverified branch and is re-challenged.
- `runGate` gains `case "help": return { action: "block", response: HELP_REPLY };` and `case "hint_missing_passphrase": { const { email } = extractCredentials(lastText!); return { action: "block", response: HINT_EMAIL_NO_PASSPHRASE(email!) }; }` — both with **no** side effects.
- `markVerified` also stamps the version: `await deps.updateUser({ verified: true, passVersion: deps.passVersion })`.
- `GateDeps` gains `passVersion: string`.
- Replace the emoji/dash strings: `CHALLENGE`, `WELCOME`, `UNCONFIGURED`, `ASK_EMAIL`, `IDENTIFY_FAIL`, `IDENTIFY_ERROR`, `LOGGED_OUT`, `identifyOk`, `verifyAndIdentifyOk`. Exact new values:

```ts
import { crmClientFromEnv, type CrmClient } from "../../lib/crm-client";

export class CrmOverviewTool implements LuaTool {

  description =
    "Answer org-level questions about the CRM itself: what it is for, how many opportunities are in the pipeline, how many investors are on file, capital raised year to date, and which stages hold the most records. ```ts
```
```ts
export interface ResearchDeps {
  generate: (opts: { model: string; system: string; prompt: string }) => Promise<{ text: string; sources?: ResearchSource[] }>;
  model?: string;
}
export class ResearchPublicProfileTool implements LuaTool {
  name = "research_public_profile";
  description =
    "Search public web sources for a background brief or recent news on a company, investor or person, and return it clearly labelled as public information rather than CRM data. Pass the entity name exactly as the user said it, its kind, and an optional focus such as 'recent news' or 'ownership'. Never pass a deal codename, an amount, or anything else confidential: this leaves Noblestride for a public search. The result is read-only context and must never be fed into propose_change.";
  inputSchema = z.object({
    name: z.string().min(2).describe("Public name of the company, investor or person"),
    kind: z.enum(["company", "investor", "person"]),
    focus: z.string().optional().describe("Optional angle, e.g. 'recent news', 'ownership', 'leadership'"),
  });
  constructor(private deps?: ResearchDeps) {}
  private getDeps(): ResearchDeps {
    return this.deps ?? {
      generate: (o) => AI.generate({ model: o.model, system: o.system, prompt: o.prompt })
        .then((r) => ({ text: r.text, sources: r.sources as ResearchSource[] | undefined })),
      model: env("RESEARCH_MODEL") || "google/gemini-2.5-flash",
    };
  }
  async execute(input: z.infer<typeof this.inputSchema>) {
    if (isConfidentialLeak(input.name) || (input.focus && isConfidentialLeak(input.focus))) {
      return { status: "unavailable" as const, label: PUBLIC_LABEL, brief: null, sources: [],
        message: "That query carries a deal codename or an amount, which must never leave Noblestride in a public search. Give me the public company or investor name instead." };
    }
    const { generate, model } = this.getDeps();
    try {
      const r = await generate({ model: model ?? "google/gemini-2.5-flash", system: RESEARCH_SYSTEM, prompt: buildResearchPrompt(input) });
      return shapeResearch(r.text, r.sources);
    } catch {
      return { status: "unavailable" as const, label: PUBLIC_LABEL, brief: null, sources: [],
        message: "Public search is not available right now. Please try again shortly." };
    }
  }
}
```
`google/gemini-2.5-flash` is a real id in `lua models list`; the Google family is what populates `sources` (Google Search grounding). `RESEARCH_MODEL` overrides it without a code change.
